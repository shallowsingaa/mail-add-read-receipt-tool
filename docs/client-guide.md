# 客户端使用说明（一步一步教你用）

这份说明写给**第一次使用本工具的普通人**。你不需要懂编程、服务器或邮件协议，只要会解压文件、复制粘贴、填写几个空就行。

如果你要部署服务端（自己架服务器），请看文档目录里另外几份部署指南；本文只讲**怎么用 Windows 客户端**。

---

## 一、这个工具是做什么的？

假设你想知道：**对方有没有打开过我发的邮件？**

本工具的做法是：

1. 你用客户端创建一条“追踪链接”。
2. 客户端生成一小段 HTML 代码。这段代码里有一张**肉眼看不见的透明小图**，图片地址指向你自己的服务器。
3. 你把这段代码粘贴进邮件，再正常发送。
4. 对方打开邮件时，邮件软件通常会去加载这张图片。
5. 你的服务器发现“有人来取这张图了”，就立刻**发一封通知邮件**给你，告诉你：大约在什么时间、用什么方式访问的。

这样你就能看到“邮件里的图片被访问过”，从而大致判断对方是否打开过邮件。

### 请务必先记住三件事

| 事实 | 说明 |
| --- | --- |
| **不等于“确定已读”** | 有些邮箱（尤其是 Apple 邮件）会提前下载图片；公司邮箱、代理、缓存也可能造成“看起来访问了，其实人没看”。 |
| **不等于“打开几次就看了几次”** | 浏览器刷新、邮箱预加载、代理缓存都可能让访问次数变多或变少。最终以服务器实际收到的请求为准。 |
| **发送后不需要一直开着客户端** | 发通知的是服务器。客户端关机、退出都不影响；只要你不再需要管理这条链接即可。 |

工具证明的是：**服务器收到过图片请求**。它是一个参考信号，不是法院证据，也不是“已读回执”的官方标准。

---

## 二、开始之前，你需要准备什么？

| 需要的东西 | 说明 |
| --- | --- |
| **一台 Windows 电脑** | 目前提供的是 Windows 64 位客户端。 |
| **客户端压缩包** | 通常是 `receipt-client-windows-x64.zip`，由管理员或你自己准备好。 |
| **服务端公网地址** | 例如 `https://receipt.example.com`。这是管理员部署好的地址，**不是**你电脑上的 `localhost`。 |
| **一个能收信的邮箱** | 用来接收“有人访问了图片”的通知。 |
| **能写“源码”的邮件编辑器** | 例如网页版邮箱、Outlook 某些模式、或支持“编辑 HTML / 源码”的客户端。具体见第五步。 |

如果你还没有服务端地址，请先找部署的人（或自己按部署文档架好），再回来用客户端。

---

## 三、第一步：解压客户端

1. 找到压缩包 `receipt-client-windows-x64.zip`。
2. 右键 → **全部解压缩…**（或使用 7-Zip、WinRAR 等）。
3. 解压到一个**自己找得到、且可写入**的文件夹，例如：
   - `D:\Tools\receipt-client\`
   - 或桌面上的 `receipt-client` 文件夹。
4. **不要**直接在压缩包里双击运行。程序需要在同目录读写 `client.toml` 和 `history.json`，压缩包内无法保存。

解压后，文件夹里通常会有：

| 文件 | 作用 | 你要动它吗？ |
| --- | --- | --- |
| `receipt-client.exe` | 主程序，双击启动 | 每次使用都打开它 |
| `client.toml` | 配置文件（服务器地址） | **第一次必须改** |
| `README.md`、`docs\` 等 | 说明文档 | 需要时再看 |
| `history.json` | 本地历史（可能稍后才出现） | 不要删；见第八节 |

---

## 四、第二步：填写服务器地址

这一步只需做**一次**。改完以后，除非服务器地址变了，否则不用再改。

1. 在资源管理器中，进入客户端文件夹。
2. 找到 `client.toml`。
3. 右键 → **打开方式** → 选择 **记事本**（或 Notepad++、VS Code 等纯文本编辑器）。
   - **不要**用 Word 打开。
4. 把内容改成类似下面这样（只改引号里的地址）：

   ```toml
   [client]
   api_base_url = "https://receipt.example.com"
   timeout_seconds = 15
   ```

5. 把 `https://receipt.example.com` **换成管理员给你的实际地址**。

### 填地址时最容易错的地方

| 正确 | 错误 | 原因 |
| --- | --- | --- |
| `https://receipt.example.com` | `https://receipt.example.com/api` | 不要加 `/api`、`/pixel` |
| `https://receipt.example.com` | `receipt.example.com` | 要写完整的 `https://` |
| `https://receipt.example.com` | `http://127.0.0.1:8000` | 这是本机调试地址，别人收不到 |
| `https://receipt.example.com` | `https://receipt.example.com/receipt/` | 不要带路径或末尾多余内容（末尾 `/` 一般也会被自动去掉，但最好别写） |

6. **保存**文件（记事本里按 `Ctrl+S`）。
7. 如果客户端已经开着，**完全退出后重新打开**，配置才会生效。

第一次运行时，如果目录里还没有 `client.toml`，程序会自动生成一份指向本机的模板。那是调试用的，记得改成公网地址。

---

## 五、第三步：创建追踪链接

1. 双击 `receipt-client.exe`。
2. 窗口标题是 **「邮件图片请求通知工具」**。上方会显示当前 API 地址和配置文件路径——先确认地址是你填的那个。
3. 在 **「通知邮箱」** 栏填写**你用来收通知的邮箱**，例如 `me@example.com`。
   - 通知会发到这个地址，不是收件人的地址。
4. 在 **「备注」** 栏随便写一句方便自己辨认的话，例如 `发给张三的合同`。可以不填，但建议填。
5. 点击 **「创建追踪链接」**。
6. 稍等片刻，下方 **「复制下方 HTML 到邮件的源码模式」** 文本框里会出现一段 HTML 代码。
7. 状态栏会提示「已创建并保存」。本地历史里也会多出一条记录。

到这里，链接已经创建好了。接下来是**最容易出错的一步**：把 HTML 放进邮件。

---

## 六、第四步：把 HTML 粘贴进邮件（关键）

### 为什么要用“源码模式”？

生成的 HTML 是一段**网页代码**，不是普通文字。

- 如果你粘贴到邮件的**普通正文输入框**，收件人会看到一堆 `<img src=...>` 之类乱码。
- 只有粘贴到邮件编辑器的 **“源码 / HTML / 编辑源代码”** 模式，邮件软件才会把它渲染成一张不可见的图片（外加极小的占位）。

### 操作步骤

1. 在客户端点击 **「复制 HTML」**（或按 `Ctrl+Y`）。状态栏会提示已复制。
2. 打开你的邮件编辑器，**新建邮件**。
3. 找到“源码模式”入口。不同软件叫法不同：

   | 邮件工具 | 常见入口 |
   | --- | --- |
   | 网页版 QQ / 163 / Gmail 等 | 工具栏里的 `</>`、`HTML`、「源码」、「编辑源代码」 |
   | Outlook（新版） | 有时需先切换到“在浏览器中编辑”，或使用支持 HTML 的插件/模板 |
   | 专业客户端 / 公司自建邮箱 | 菜单里的「查看 → 源码」「编辑 → HTML」 |

   如果实在找不到，可以在搜索引擎搜：`你的邮箱名 如何 编辑 HTML 邮件`。

4. **切换到源码模式**后，按 `Ctrl+V` 粘贴。你应看到刚才那段 HTML 代码。
5. **再切换回普通编辑模式**（可视化模式）。此时正文区域应几乎一片空白（透明图片肉眼看不见），这是正常的。
6. 在邮件里正常写称呼、正文、签名。**可以继续用普通方式打字**，不必把整封信都做成 HTML。
7. 发送前，建议先给自己发一封测试，确认：
   - 自己能看到正文；
   - 客户端里“刷新状态”后，事件计数会增加；
   - 通知邮箱收到访问通知。

### 如果粘贴后看起来是乱码？

说明还停在普通正文模式。请：

1. 切换到源码模式；
2. 若正文已有乱码，先全选删除；
3. 重新粘贴 HTML；
4. 再切回可视化模式确认。

---

## 七、第五步：发送后如何查看结果

邮件发出去后：

1. 对方（或对方的邮箱系统）打开邮件时，服务器会记录访问并发通知。
2. 你可以在客户端里选中那条历史，点击 **「刷新状态」**。
3. 窗口中会出现类似：

   ```text
   状态：启用
   通知队列：{"pending": 0, "sending": 0, "sent": 1, "failed": 0, "cancelled": 0}
   ```

   含义见下表：

   | 字段 | 含义 |
   | --- | --- |
   | `pending` | 还没发出去，排队中 |
   | `sending` | 正在发送 |
   | `sent` | 服务器已成功交给邮箱系统（通常你应能收到） |
   | `failed` | 发送失败，超过了可重试期限 |
   | `cancelled` | 链接已停用，未完成的通知被取消 |

4. 同时去**通知邮箱**（以及垃圾箱）查看是否有新邮件。通知里会写：时间、请求方法、URL、来源 IP、请求头、备注等，供你判断是不是代理或预加载。

### 一次点击就发送了吗？

不是。流程是：

```text
对方打开邮件 → 邮箱加载图片 → 你的服务器记录 → 后台发通知邮件 → 你收到通知
```

如果网络或 SMTP 有问题，通知可能延迟。可以点「刷新状态」多看几次，或点「重新投递失败通知」。

---

## 八、管理已有链接

客户端下半部分是管理区。**先在「本地历史」下拉框里选中一条记录**，再点按钮才有效。

| 按钮 | 作用 | 什么时候用 |
| --- | --- | --- |
| **复制 HTML** | 再次复制这段 HTML | 重新粘贴、换一封邮件、补发 |
| **刷新状态** | 向服务器查询最新状态和计数 | 想知道有没有人访问、通知是否发出 |
| **重新投递失败通知** | 把失败的通知重新排队发送 | 修好 SMTP 后，或网络恢复后 |
| **停用链接** | 图片不再响应（返回 404），并取消未发出的通知 | 不想再追踪了，但想保留记录 |
| **删除记录（点两次）** | 彻底删除：服务端链接 + 请求记录 + 本地历史 | 确认不要了 |

### 删除为什么要点两次？

删除是不可恢复的：图片会立刻失效，历史和管理凭据也会消失。所以第一次点击只是“上膛”，状态栏会提示再点一次确认；第二次才真正删除。

### 停用和删除的区别

| | 停用 | 删除 |
| --- | --- | --- |
| 图片还能被访问吗 | 不能（404） | 不能 |
| 服务端记录 | 保留 | 删除 |
| 本地历史 | 保留，可再查看 | 删除 |
| 以后还能重新启用吗 | 不能（新访问一直 404） | — |

链接**不会自动过期**。只要你不停用、不删除，图片地址长期有效。

---

## 九、本地历史文件（`history.json`）非常重要

每次创建链接，客户端都会写入 `history.json`，保存：

- 通知邮箱、备注；
- 生成的 HTML；
- 当时使用的 API 地址；
- **管理凭据**（用于刷新 / 停用 / 删除）。

### 请你务必

1. **不要删除** `history.json`。
2. **定期备份**（复制一份到网盘或 U 盘即可）。
3. 换电脑时，把整个客户端文件夹一起拷过去，或至少带上 `client.toml` + `history.json`。

### 丢了会怎样？

- 图片**不会**自动失效，已发出的邮件仍然可能被访问。
- 但你**无法**再通过客户端管理那些旧链接（不能刷新、停用、删除）。
- 如果你不再需要它们，可以忽略；若必须下线旧链接，请找管理员在服务器端处理。

### 换了服务器地址呢？

`client.toml` 里的地址只影响**新创建**的链接。历史里每条记录记着**它自己当时**的服务器地址，管理操作仍打向旧服务器。旧记录不会自动搬家。

## 十、键盘操作与窗口

| 按键 | 作用 |
| --- | --- |
| `Tab` | 在输入框和按钮之间切换焦点 |
| `Enter` | 激活当前聚焦的按钮（或提交输入） |
| `Ctrl+Y` | 复制 HTML |
| `Ctrl+Q` | 退出程序 |

- 窗口较小时，中间区域可以**滚动**。
- 按钮上的文字会提示二次确认（删除）。
- 程序退出后，历史已写入磁盘；通知仍由服务器发送。

## 十一、常见问题

### 1. 打开 exe 就闪退 / 提示“启动失败”

- 确认是**解压后**在文件夹里运行，不是压缩包内。
- 看 `client.toml` 是否被改坏了（必须是合法 TOML：引号、等号齐全）。
- 路径中尽量避免异常权限目录；换到 `D:\Tools\` 之类再试。
- 用记事本打开 `client.toml`，对照第四节示例检查。

### 2. 提示连接失败 / 超时

- 核对 `api_base_url` 是否写对（`https://` + 公网域名）。
- 确认你的电脑能打开该网址（浏览器访问 `https://你的域名/health` 应看到 JSON）。
- 公司网络、代理、防火墙可能拦截；换网络或找管理员。
- `timeout_seconds` 可适当调大（如 `30`），然后重启客户端。

### 3. 创建时提示 HTTP 429

创建太频繁，触发了限速（默认每小时约 20 条，以服务端配置为准）。等一会儿再试，或找管理员调整。

### 4. 创建时提示 HTTP 422

邮箱格式不对，或备注过长/含非法字符。检查通知邮箱是否写完整，例如 `you@example.com`。

### 5. 创建时提示 HTTP 404

管理操作（刷新/停用/删除）可能对准了错误服务器，或记录已不存在。确认历史里那条记录的 API 地址是否仍是当前服务器。

### 6. 粘贴进邮件后是乱码

见第六节：没有切到源码模式。请切到源码/HTML 模式后重新粘贴。

### 7. 发了测试邮件，但收不到通知

按顺序检查：

1. 客户端点「刷新状态」，看事件计数是否增加。  
   - **没增加**：图片没被真正请求到。检查邮件是否真的加载了远程图片，或链接是否已停用。  
   - **有增加**：问题在发信环节。
2. 看通知队列是 `pending` 还是 `failed`。
3. 查通知邮箱的**垃圾箱 / 推广 / 隔离区**。
4. 若是 `failed`，点「重新投递失败通知」。
5. 仍不行，联系服务端管理员检查 SMTP。

### 8. 对方说“我根本没打开”

这是正常现象，不代表工具坏了：

- 邮箱预加载、代理、爬虫、安全网关都可能访问图片；
- 对方也可能确实打开了但客户端缓存了图片，没有回源。

请结合通知里的 IP、User-Agent、时间综合判断，不要只看“有一次访问”。

### 9. 一封邮件发给多个人，能知道是谁打开的吗？

**不能。** 同一条链接发给多人时，只能知道“有人访问了”，无法区分是哪一位。

若必须区分：给每个人**单独创建链接**，并**分别发送**邮件。

### 10. 隐私与合规

- 请只对自己的合法邮件使用，并遵守对方隐私与所在地区法规。
- 通知中会包含请求头、IP 等技术信息，属于你方服务器日志性质数据，注意保管，不要随意转发。
- 工具不抓取邮件正文，只记录“图片请求”。

---

## 十二、完整流程速查（给已经会用的人）

```text
1. 解压到可写文件夹
2. 改 client.toml 里的 api_base_url（一次）
3. 打开 receipt-client.exe
4. 填通知邮箱（和可选备注）→ 创建追踪链接
5. 复制 HTML → 邮件源码模式粘贴 → 切回正常模式写正文 → 发送
6. 之后用「刷新状态」查看；失败用「重新投递」
7. 不需要时「停用」或「删除」；备份 history.json
```
